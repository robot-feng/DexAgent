压缩包只有 8.4 KB，包含中文说明、BibTeX、manifest、官方 arXiv 链接和下载脚本，**不含六篇论文 PDF**。本次没有运行压缩包脚本；我通过 arXiv 官方全文页面阅读六篇论文的方法、实验和限制章节，并核对了 DexAgent、SimFoundry、ARSTAG、Video2World、Dex-One2Many 与 RoboSimStudio 的官方项目/源码入口。DexAgent 与 SimFoundry 的 arXiv PDF 下载完成且文件头、`pdfinfo` 校验有效；其余论文以官方全文 HTML 为阅读依据。

压缩包的定位和论文 ID 可用，但元数据不是项目实现规范：RoboSimStudio 的论文标题在 manifest 中比官方标题少了 “Human and Agent”；正式引用或自动化处理应以 arXiv 当前版本为准。ARSTAG 和 Dex-One2Many 的资料包只给项目页，没有声称有完整开源算法仓库；项目页存在不代表训练/重建实现可直接复用。

## 六篇工作的核心方法与适用范围

### 1. DexAgent：把适应性、阶段校验和工具积累放进一条人类演示到机器人数据链

DexAgent 把单段第一人称人类演示与任务指令转成机器人轨迹和策略训练数据。四阶段为：语义理解与子目标分解、按对象属性重建场景、逐子目标生成/优化机器人轨迹、在仿真中扰动物体和机器人状态并渲染数据。每个阶段根据对象属性选择 skill；缺少合适能力时才开发可复用的新 skill。Verifier 以仿真交互检验几何、结构、接触、稳定性和任务结果，失败反馈驱动有限修正；工具以带类型参数的普通 Python 函数存在，修改新建分支而不是覆盖原版。[论文](https://arxiv.org/html/2609.35318v2) · [源码](https://github.com/dexagent1/DexAgent)

Stage 2 不只看物体网格是否好看：刚体检查轮廓、尺度、质量与静置稳定，关节物体检查关节存在性/轴/范围，柔体检查拓扑；场景放置还用同视角渲染 mask 与源视频做对齐。Stage 3 对抓取或接触目标做物理测试，只把通过验证的关键姿态连接成轨迹；完整 episode 再检查限制和物理一致性。Stage 4 对已验证动作重新实例化到可达物体/机器人状态，并单独做视频清理、合成和重纹理。

论文报告十一类真机任务上的提升，但同时明确承认语义/几何错误、Verifier 覆盖不全和 sim-to-real 差异仍会导致错误通过和错误传播；受力敏感的任务可能通过仿真检查后仍然失败。因此系统应积累可审查、可回归的工具与证据，不应把“Verifier 通过”当作物理真值。

**对 EmbodiForge 的用法：** 保留 DexAgent 阶段、工具库、任务子目标与修复反馈机制；把工具晋级、模型输出和阶段报告绑定样例/版本/测试证据。Verifier 按当前任务涉及的性质组合，不要求每个场景运行同一份大检查清单。新的 tool library 能力必须参数化，且经过不同资产/配置回归后才能共享。

### 2. SimFoundry：前景可交互资产与干净静态背景是两条互补分支

SimFoundry A 流程先从场景扫描视频选代表帧，做深度与地面/世界对齐；场景模型提出前景类别，图像分割器逐对象提 mask 并反复从 RGB-D 中扣除；每个对象单独生成视觉网格、回到全场景估姿，并生成碰撞代理和物理参数。重建物体进入物理环境做穿插修正与稳定化。B 再做对象、场景、任务层面的 Digital Cousins；C 提供评估、演示/轨迹应用。论文在多任务多策略评测上报告仿真评估与真实策略表现相关，但这只是该实验集合的证据，不保证任意新场景都对齐。[论文](https://arxiv.org/abs/2606.28276) · [源码](https://github.com/NVlabs/SimFoundry)

自动背景重建不是普通 Stage 2c 高斯训练的别名。它从同一原始视频复用相机轨迹，按以下链路独立产出背景：

1. 从一张关键帧枚举要移除的前景类别；图像分割产生像素 mask，视频分割模型传播成逐帧 mask。
2. 两遍、分块运行视频补洞，第一遍补全主体区域，第二遍细化残余伪影。
3. 对原始帧运行 DA3 取得不受补洞影响的相机位姿；对补洞帧运行 DA3 取得和补洞 RGB 一致的深度与置信度。重叠块用 Umeyama 对齐，补洞深度点云还要与原始相机世界对齐。
4. 用补洞 RGB 和对应深度监督 Gaussian Splat，并对每个相机的小位姿残差做优化；最后用共同锚帧将 splat 桥接进前景场景坐标系。

论文比较了同视频全自动路径与第二段空场景视频的人工路径：第二段空场景视频通常边缘更锐利，但需要用户重新拍摄并在编辑器中手工做尺度和位姿配准。自动路径适用于没有原始空场景视频的输入，但补洞区是图像推断，不是实际观测或碰撞测量。[自动/手工背景细节](https://arxiv.org/abs/2606.28276)

**对 EmbodiForge 的用法：** 分别保存背景视觉表示、可碰撞支撑结构、任务物体实例和机器人。背景 mask 要包含扫描时静止的机器人/物体；对象实例和静态背景不能只靠运动检测区分。mask 质量检查通过后才补洞，补洞通过后才训练背景并做坐标桥接。渲染出来没有残影与可交互碰撞正确是两条不同验收。

### 3. ARSTAG：任务相关实体筛选、实例身份绑定和支撑关系修复

ARSTAG 输入一张工作区 RGB 图与任务文本，先生成 typed scene graph：只选择完成当前任务所需的实体、支撑物和空间关系。每个图节点有实例描述，SAM3 生成候选 mask；再由视觉属性和相对位置建立对象到 mask 的局部一对一对应，避免两个同类杯子误绑到同一 mask。未匹配节点会显式报告，而不是任意继续造资产。

它将单体 3D 重建的初始姿态与图里的 support 关系结合，做有界的支撑几何修复（例如先调平桌面，再传播支撑物姿态并对齐接触高度），然后构造仿真并让物体落稳。任务执行前还用场景碰撞、工作空间/进场空间与 IK 条件筛除不可执行 grasp/layout；随机化扩大物体和环境分布，但保持任务关系不变。[论文](https://arxiv.org/abs/2609.24563)

论文在七类桌面任务上展示了生成数据的真机迁移；限制包括小物体堆叠/螺丝插入的精度、较长串联任务的数据覆盖不足。它使用的任务筛选和空间修复不能被泛化为全场景重建，也不能证明从单张 RGB 能恢复任意深度或关节结构。

**对 EmbodiForge 的用法：** 继续用 DexAgent 的任务语义契约作为权威来源，不新建第二套场景 DSL；在任务映射时增加可验证的实例绑定与支撑关系。低置信度或同类多实例不清晰时停止下游或要求一次人工确认。刚体候选布局在采集前先做碰撞/工作空间/IK 可行性筛查，避免把无效布局批量展开。

### 4. Video2World：分别测“能运行、长得像、运动像、任务完成”

Video2World 把 video-to-simulation 看成 coding agent 迭代工程任务：查看输入视频和工具、写场景与机器人行为、执行仿真、用 rollout 反馈修订，最后提交冻结版本。其基准含 222 个重建实例、189 个视频、39 类任务；测量分为 build/executability、初始几何、演示物体动态和功能正确性。几何分数会对操作对象、接收对象和相关支撑区域加权；功能分数检查初始条件、必需交互事件顺序及最终目标，并同时报告成功和中间进度。[论文](https://arxiv.org/abs/2610.04432) · [基准与代码](https://github.com/AetherLabsAI/Video2World)

关键结论是“看上去更像”不代表任务成功更高：agent 系统的可执行 build rate 可以很高，任务成功仍显著落后；人类协助结果也没有达到所有任务都可靠。反过来，执行失败也未必只由场景引起，可能来自重建、策略或两者交互。因此系统不能把一张静帧、一个高斯背景、一次成功的 build 或单一总分当作最终验收。

**对 EmbodiForge 的用法：** 把每个 stage 的质量证据按四类记录：可执行性、对象/背景几何、对象运动/接触动态、任务子目标与终态。先作为分项报告和失败诊断，不直接照搬论文加权公式；待有本地标注样例后再校准阈值。支持里程碑进度，但只在必需条件全部满足时把 episode 标为任务成功。

### 5. Dex-One2Many：从示范中取任务关系，而非复制某条运动

Dex-One2Many 把人类演示抽象为按时间排序的 scene graphs。节点是手、任务对象和功能部位；边是 `pre_grasp`、`grasp`、`contact`、`inside` 等关系。进入新阶段由谓词关系变化决定，已建立关系会继续保留。它让关系图约束不同初始状态/抓取的 reset 分布，并把几何/物理谓词转成观测量、稠密奖励与阶段目标，训练策略去重新发现动作，而非逐帧照搬示范姿态。[论文](https://arxiv.org/abs/2610.12470) · [项目页](https://dex-one2many.github.io/)

这对“一条演示生成很多不同轨迹/数据”的泛化有启发；它不是视频场景扫描或网格重建方案。论文也指出单视频的关节轴/范围很难可靠识别，且实机仍受物体位姿估计与仿真几何差异影响。

**对 EmbodiForge 的用法：** 在现有 Stage 1 子目标上渐进加入谓词变化和对象相对关系，例如 approach → grasp/contact → transport → release/inside；先给 RSS 的任务 gate 和变化生成提供结构，不急于另造 RL 系统或扩展 SceneSpec。若后续做策略学习，可复用这些关系定义生成 stage reset、进度指标和任务一致的随机化约束。

### 6. RoboSimStudio：把 Real2Sim 做成可交互的“改场景—跑动作—看反馈—再修正”循环

RoboSimStudio 的贡献核心是共享的可编辑仿真工作台，而不是只换一个物理引擎。它让人和 coding agent 检查场景、运行机器人动作，显式调整 solver、contact model、刚度/阻尼/摩擦等参数；Agent 可读到目标误差、物体运动、接触、抓取/滑移和任务进度，针对真实视频与仿真差异迭代。必要时可以由不同 solver/外部引擎耦合不同物理对象；配置保存在场景里，任务程序无需重写。[论文](https://arxiv.org/abs/2610.18835) · [源码](https://github.com/robosimstudio/robosimstudio)

论文用 18 个不同接触/变形任务展示交互能力，并以一个双臂擦拭任务作 agentic Real2Sim2Real pilot。论文承认 agent 受现有资产/solver 能力限制、外部耦合降低吞吐，真机迁移量化实验还只有一个任务且主要为定性。因此它支持“可迭代调参和失败修正”这个架构选择，不支持宣称多物理仿真已普遍精准。

**对 EmbodiForge 的用法：** RSS 负责目标运行时的执行、交互物理检查、调参与原始 episode 记录。Agent 使用现有 RSS 状态/episode 接口获得反馈，不在 Workbench 重写 viewer 或物理内核。第一次只开放当前任务需要的参数与比较视图；同一组动作/初始条件对比不同 scene/physics revision，并保留真实失败如何改变仿真约束的来源记录。

## 六篇论文合起来，对系统架构的实际修订

这些工作不是要求把各自阶段和模型逐个照搬，而是共同要求形成一条证据驱动的闭环：

```text
输入路由
  ├─ 场景扫描：原视频 → 前景身份/mask → 清理帧 → 静态背景重建
  │                         └→ 独立对象/支撑/机器人资产 → 姿态与物理校验
  ├─ 操作演示：任务/实体 → 阶段关系图 → 人类动作/接触线索
  └─ 已有资产/任务：校验来源和坐标，不重复重建
                  ↓
             RoboSimStudio 目标运行时
                  ↓
       执行反馈 → 定位失配 → 有界修复 → 重跑验收
                  ↓
       任务一致的布局/物理变化与数据生成
                  ↓
       分项质量证据 → EpisodeStore → 独立导出检查
```

1. **统一工作流和产物来源，保留工具链环境边界。** 不统一 Python 环境，也不新建模型市场/第二套场景标准。控制面保持 DexAgent/Workbench 现有入口；SimFoundry 重型视觉重建继续在上游环境跑；RSS 是目标运行时。每个阶段在现有契约中明确输入、输出、状态和证据。
2. **场景必须按用途分层。** 至少区分 `background_visual`、`support_collision`、动态/任务对象、机器人/手，以及关节/柔体实体。每份几何标注“实测/重建估计/模型补洞/人工确认”；无背景深度证据的补洞像素不可进入碰撞代理。隐去一个实例后，静态图像背景与可交互碰撞要分别验收。
3. **分割器和传播器是能力角色，不是模型名字。** `image_segment(prompt, image) → instance masks` 与 `video_segment(prompt|seed_masks, clip) → per-frame instance masks + confidence` 是两个稳定边界。SAM3 单模型可同时承担两种角色，SAM3+SAM2 也可拆分承担；按同视频比较覆盖率、漏检、漂移、遮挡恢复、耗时、显存和实例保持情况后选默认。两种模式都必须保留同构 mask 预览/校验。
4. **操作识别转成关系和阶段谓词。** 保留当前任务对象与子目标 JSON，将其轻量增强为对象身份绑定、支撑/接触/包含关系、前置与完成谓词，以及每个关系的可测量来源。关系为已观察/推断/用户确认，并指回视频帧或仿真状态；不对所有对象强行推断绝对深度。
5. **每个门禁检验对应失败面。** 构建失败、实例漏绑、坐标/尺度不符、背景/深度错误、碰撞/穿插、运动偏差、任务谓词未满足、记录/导出损坏分别保留独立证据。实现层面可先用硬条件与定量指标，再提供综合摘要；综合分数不能让硬失败被其它高分抵消。
6. **样本扩增保持任务关系。** 先按可达空间/碰撞/IK 过滤布局；只对被任务关系允许的对象位姿、干扰物、场景尺寸/光照/相机、执行误差做随机化。每个正式 episode 仍需在 RSS 重新执行并通过任务 gate。
7. **修复预算有限且可复现。** Agent 从具体失败报告回到相应阶段，限定次数、输入哈希、资源预算和停止原因；通过的旧产物不覆盖。共享 Skill/Verifier 或模型版本变化必须记录新 SHA、重新做相关回归。

统一的轻量 provenance manifest 至少记录：输入视频/资产哈希、输入类型、任务版本、各阶段代码 commit、配置摘要和随机种子、所选模型/权重 revision/SHA/环境/许可、产物哈希、坐标系/单位、几何来源类别、阶段状态、失败/重试链、质量指标、RSS 场景/物理配置和 EpisodeStore ID。它是来源索引，不复制为第二份运行状态或场景真值。

## 对当前实施计划的优先级建议

1. **先完成并固定当前基础链路。** SimFoundry 主环境与剩余官方工具环境安装结束后，跑 `ThrowAwayTrash.mp4` 冒烟测试；明确它只验证流程，不声称是实际扫描视频。检验前景类别是否包括机器人/手和操作对象、mask 能否双向覆盖、补洞视频是否残留，以及 auto-bg 是否把背景对齐到场景坐标。
2. **完成一次实际背景去除闭环。** 保留原始帧、关键帧实例 mask、逐帧 mask 视频、mask 元数据、VOID 两遍清理帧、DA3 深度/置信度和 splat 变换。用用户确认的对象列表审查 mask 与清理视频；如 mask 漏掉机器人，不进入昂贵的补洞/建图阶段。
3. **用 Video2World 的分项验收补足 P3/P4。** 对同一个 smoke case 依次确认：可构建；实体身份与初始位置/尺度可检查；机器人/对象运动对齐源视频里程碑；RSS 完成任务并满足终态谓词。只对已具备真实标注的量设数值门槛。
4. **再做关系驱动的批量扩增。** 在 RSS 中用已验证刚体任务生成少量 task-consistent variants，验证任务谓词和执行 gate，再扩展批量与格式导出。每步保留真实失败导致的修正证据，避免只以渲染逼真度为优化目标。

`ThrowAwayTrash.mp4` 是当前已授权的冒烟输入，不代表原始用户扫描视频。用户当前没有原始场景扫描视频，因此原场景里已烘焙进旧网格的机器人不能用新 mask 追溯性消除；需要新输入重新跑清理与重建。

## 本机素材与实验本体补充（2026-10-20）

用户指定 `GenieSimAssets` 作为对象、背景、材质和 HDR 来源。根据最新澄清，**严格 Real2Sim 复现保留源场景和原本体；Ego 等可迁移任务采用公共桌面，至少在现有 Sharpa 灵巧手、G1 Omnipicker、G2 Omnipicker 三套本体上分别通过**。可迁移任务须分别规划、物理执行、判定和记录，任一未验证都使该 demo 未完成；严格复现按源本体和源场景验收，不强制替换公共桌子。目标随任务明确，不能为绕过失败自动切换。本机资产仍须按目标运行时验收，尤其不能把任务专用 `G2_place_workpiece.xml` 当作 G2 Omnipicker 的等价模型。后续沿 RSS 已有本体/夹爪接口与现有编辑器资产入口接入，不新增一套场景或机器人框架。详细检查与规则见 [GenieSim 素材与本体审查](GENIESIM_ASSET_ADOPTION_20261020.md)。

## 已落实到代码的首个增量

依照“目标引擎重新验收”和“可执行、视觉、任务结果分开计量”的结论，已将 SimFoundry 刚体产物接入统一 CLI、RSS 静置/接触检查、原生记录、诊断视频及 Workbench 三维状态回放。16 项资产/录制相关测试和 55 项 Workbench 测试通过；合成立方体跑完统一入口并在默认 8765 实际浏览。资产身份变化或物理漂移超限会明确失败，成功记录仍标注非训练样本。详见[实现与验证](SIMFOUNDRY_RSS_IMPORT_20261020.md)。当前证据仅覆盖合成文件契约；真实 SimFoundry 视频重建、背景清理和任务级验收尚未完成，不能据此称三个项目已完整融合。
