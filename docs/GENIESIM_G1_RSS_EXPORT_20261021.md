# G1 完整模型导出与 RSS 位置控制资格

本阶段验证源 USD → Newton/native MuJoCo → 可追溯 MJCF → RSS Scene 的模型和控制链路。
这是明确适配后的机构资格，**不是保真重建通过、抓取通过或训练 Episode**。G1 的源保真
检查仍保留失败；G2 和现有 YAM + Sharpa 的同任务验收不因本阶段而改变。

## 完整源模型重新导入

重新导入真实 `GenieSimAssets/robot/G1_omnipicker/robot.usda`，复用 RSS
`add_usd_stage` 与既有 GenieSim 匿名 session 适配。六个源 USD 层 hash 前后相同；
源缺失的装饰相机依赖仍按既有明确例外停用，没有替换机器人或写入源文件。

此次实际模型有 42 个机器人 body、34 个标量坐标、20 个驱动、6 条等式和 3128 个
native geom。四个末端指面共 3114 个凸分块，在 builder 和 native 两层均确认
`gap=.001 m, margin=0`；其余几何未被统一改成这个值。新的 CoACD 分解与此前
3136 个 geom 的冻结模型不同，因此不能把两者的接触表现当作只改一个参数的对照。

保留三类失败：四个闭环 child anchor 的导入偏差、三个辅助 body 的 finalize 惯量
变化、两个源驱动目标越界。导出器保持实际 native 模型，不将这些差异改写为源保真通过。

## 固定 native 快照导出

新增 `agent/rss_mjcf_export.py`，复用同一次 Newton solver 构造的 XML 和当前 CPU
native 模型。它不是另一套资产注册表或通用场景转换框架。

- 校验拓扑、几何、质量惯量、驱动、限位、碰撞过滤和等式，再补入明确支持的 native
  solver 参数和重力补偿；质量、形状、增益、力限等不匹配会拒绝导出。
- 源生成驱动按实际 native joint → Newton joint/DOF/target 映射命名；导入的直接
  actuator 保留唯一完整标签。G1 的 20 个空名称已变为有来源的驱动身份，不靠数组
  序号猜测左右手或复制其他本体映射。
- 输出先编译、重新读取并比较，成功后才发布。原构造 XML 和模型不修改，记录各自
  hash、每个修复字段及映射。源 force-space 限位增益在此成为固定 native solref，
  不宣称可编辑 Newton 语义的无损往返。
- 空、固定且质量和惯量均严格为零的辅助 frame，其 COM 表示可被编译器规范化；
  body pose 仍检查。有质量或惯量的 body 不适用此例外。旋转按单位四元数等价性、
  惯量按 body frame 张量比较，避免主轴或 q/−q 的表示差异被误判为物理变化。

首个完整模型导出因空 frame 的 COM 表示差异被拒绝，失败记录保留。核对几何和惯量
意义后修正比较方式，再从同一个仍存活的源模型导出成功；没有重新构建或执行物理。

## RSS 验证协议

使用实际 `RSS Scene(cell='void')`、CPU backend 和 `CpuPositionTargetOutlet`。
不添加校准块或桌面，不把机构空载动作写成操作任务。RSS 自带地面须单独登记，
不能把它算作源模型几何。RSS 要求偶数子步，采用
500 Hz 控制帧、每帧两个 1 ms 子步；控制写入和验收均在各物理子步回调执行。

协议为 1900 步：保持零位、平滑至 0.1 rad、保持、平滑返回、稳定等待。其他 18 个
驱动保持初始实测位置。沿用先前明确记录的四个源闭环锚点恢复、六等式响应和 42 个
body 重力补偿；源驱动增益、力限、几何和所有停止门槛不变。

实际 Newton q/qd/body pose 与独立 native 当前 FK 对齐；每子步检查闭环、mimic、
关节限位、速度、努力限幅、接触、时钟、有限性和 warning。失败样本保存后直接中断
RSS 子步循环。非物理调度自检已证明 post hook 取得新状态且可阻止下一子步；
这项自检不替代完整模型物理执行。

## 本机证据与后续边界

实际 RSS 零步预检失败，**没有执行 1900 步协议**：geom 数量多一个、重力符号
相反、geom solref 不同。地面来自 RSS 编译器，仍需检查实际身份；重力是实验
脚本传入正值的错误，已修正，旧失败脚本和报告保留。solref 是导入缩写问题：
原生 `solref="0.02"` 表示 `(0.02,1)`，Newton 1.6 的 custom-attribute 通道却按
未赋值 sentinel 补成 `(0.02,0)`。导出器现按已编译值展开完整向量后再检查，
真实小模型 RSS 零步前后对照确认参数保留；旧完整 G1 XML 未被覆盖。

导出器还补齐版本感知的动力学字段比较、非有限值/非单位四元数拒绝及 unsupported
site/height-field 拒绝。MuJoCo 3.12/3.13 各 **16 passed**。既有 G1 XML 对原 MJB
的加强比较通过，但这不撤销上述 RSS 重载失败。

用户随后要求最新 Newton 的 GPU 并行路径优先，因此本阶段停止扩大 CPU 诊断，
保留可复用导出修复和所有失败证据，转入版本一致的 GPU 环境验证。

详细模型、构造日志、失败、协议和逐项检查保存于
`.workbench/previews/geniesim-g1-portable-20261021/`。大型模型留在本机，仓库仅保留
代码、必要测试与摘要。此前接触冲击失败及源保真失败独立保留。

MuJoCo 3.13 仍超出当前 Newton 1.6 声明的 `~=3.12` 依赖范围，本阶段仅检查指定 CPU
环境，不宣称全面兼容或 GPU 验证。机构资格通过后，还需验证接触后的控制、实际抓取、
共享桌面任务和三本体同任务覆盖，才能形成有效训练数据。
